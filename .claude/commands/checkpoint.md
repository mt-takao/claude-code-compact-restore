これまでの会話を振り返り、`.claude/context/working-notes.md` を更新してください（なければ新規作成）。
このファイルはセッション開始時と圧縮（手動・自動）の直後に自動でコンテキストへ注入されます。
個人の作業ノートでありコミットされません。

ルール:
- 既存の内容は捨てずに統合する。古くなった記述は更新・削除してよい
- 「なぜそうしたか」を1行で添える。会話の経緯や試行錯誤の過程は書かない
- 全体で 80 行以内。超える場合は完了済みの項目から要約・削除する
- 秘密情報（APIキー、パスワード、個人情報）は絶対に書かない

セクション構成（見出しはこのまま使う）:
1. `## ゴール` — 今取り組んでいることと完了条件
2. `## 確定した決定事項` — 決めたことと理由（覆すにはユーザー確認が必要なもの）
3. `## 却下した案` — 同じ提案を繰り返さないため、案と却下理由
4. `## 現在地` — どこまで終わり、今何をしている途中か
5. `## 次にやること` — 具体的な次の一手
6. `## 未解決の論点` — ユーザー判断待ち・保留事項

**クラウドセッションの場合**（セッション開始時に「クラウドセッションでの記録先」の案内が出ている場合）は、さらに次を行ってください。
- 未コミットの変更があれば、作業ブランチに commit して push する
- Claude Code Projects のスレッドであれば、「確定した決定事項」「却下した案」と、作業中に見つけた落とし穴のうち
  後続のスレッドにも必要なものを **プロジェクトメモリ** に記憶する。すでに記憶済みの内容は重複させない

補足メモ: $ARGUMENTS

手動で `/compact` を実行できる環境なら、最後に今の状況に合った `/compact <focus>` の例を1つ提示してください。
Projects のスレッドなど自動圧縮のみの環境では、この提示は不要です。
